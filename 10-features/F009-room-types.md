# F009 방 종류

## 목적
층마다 방 구성이 달라서, 어떤 방을 먼저 뒤질지·위험을 감수할지 고르게 한다. 비밀방과 퍼즐방은 **찾고 풀면 좋지만 없어도 클리어할 수 있는 보너스**다. 단서를 보고 찾는 것이지, 운으로 찾는 것이 아니다(P4).

## 방 종류
| id | 이름 | 하는 일 | 층당 개수 |
|---|---|---|---|
| `start` | 시작방 | 플레이어 시작 지점. 몬스터·함정 없음 | 1 |
| `stairs` | 계단방 | 계단이 있는 방 (1~9층) | 1 |
| `boss` | 보스방 | 10층 (F008) | 10층에 1 |
| `normal` | 일반방 | 몬스터와 바닥 아이템 | 1 이상 |
| `treasure` | 보물상자방 | 상자 1개, 빌드 아이템 셋 중 하나 (F005) | 1~2 (1~9층) |
| `secret` | 비밀방 | 숨은 입구. 희귀 빌드 아이템 둘 중 하나 | 0~1 |
| `puzzle` | 퍼즐방 | 퍼즐을 풀면 잠긴 상자가 열림. 빌드 아이템 셋 중 하나 | 0~1 |
| `spring` | 샘방 | 회복의 샘 1개 | 0~1 |

## 방 종류 정하기
1. F001이 만든 방 목록에서 먼저 `start`, `stairs`(또는 `boss`)를 정한다. 이 방들은 다른 종류를 겸하지 않는다.
2. 나머지 방은 테마의 `roomWeights` 가중치로 종류를 정한다(`rooms` 난수 흐름).
3. 종류마다 rooms.json의 `minPerFloor`, `maxPerFloor`를 지킨다. 단, 그 테마의 가중치가 0인 종류는 `minPerFloor`를 무시한다(10층에 보물상자방이 없는 이유).
4. 방 크기가 그 종류의 최소 크기(rooms.json `minRoomSize`)보다 작으면 그 종류가 될 수 없다. 퍼즐방은 들어갈 퍼즐 판이 있는 크기여야 한다(아래).
5. 최소 개수를 채울 수 없으면 `normal`을 줄여서 채운다. 그래도 안 되면 경고 로그를 남기고 넘어간다.
6. F005 규칙 10(보물상자방 최소 1개)은 이 규칙으로 대신한다(rooms.json `treasure.minPerFloor: 1`).
7. 같은 시드면 같은 방 종류 배치가 나온다.

### rooms.json
```json
{ "roomTypes": [
  { "id": "normal",   "name": "일반방",     "weight": 60, "minPerFloor": 1, "maxPerFloor": 99, "minRoomSize": 4 },

  { "id": "secret",   "name": "비밀방",     "weight": 6,  "minPerFloor": 0, "maxPerFloor": 1,  "minRoomSize": 4 },
  { "id": "puzzle",   "name": "퍼즐방",     "weight": 9,  "minPerFloor": 0, "maxPerFloor": 1,  "minRoomSize": 6 },
  { "id": "spring",   "name": "샘방",       "weight": 8,  "minPerFloor": 0, "maxPerFloor": 1,  "minRoomSize": 4 }
] }
```

## 비밀방
8. **입구 만들기 (`map` 난수 흐름):** 비밀방은 다른 방과 통로로 잇지 않는다. 대신 가장 가까운 통로나 방에서 비밀방 쪽으로 **2~3칸짜리 막다른 통로**를 내고, 그 끝과 비밀방 사이의 벽 1칸에 숨은 벽(`hiddenWall`)을 놓는다.
9. 막다른 통로를 낼 수 없으면 그 방은 비밀방이 되지 않고 일반방으로 바뀌어 보통 통로로 이어진다.
10. **단서:** 지도의 막다른 통로는 비밀방 입구에만 생긴다. 다른 곳에는 막다른 통로가 없다(F001 생성 결과에 막다른 통로가 없어야 한다). 그래서 "길이 이상하게 끊긴 곳"이 곧 단서다.
11. 숨은 벽은 발견 전에는 벽과 똑같이 그리고, 지나갈 수 없고, 시야를 막는다.
12. **찾기:** 플레이어가 숨은 벽과 상하좌우로 맞닿은 칸에서 **쉬기(Space)** 를 하면 그 벽을 발견한다. 확률은 없다. 발견하면 `discovered: true`, 지나갈 수 있고 시야를 막지 않는다(열린 통로 그림). 메시지: "벽 틈으로 바람이 새어 나온다. 숨은 통로를 찾았다!"
13. 몬스터는 숨은 벽을 지나지 않고, 길 찾기에서도 벽으로 본다(발견 뒤에는 통로).
14. 보상: 방 가운데 상자 1개. 열면 F005 규칙 12의 비밀방 규칙(희귀 둘 중 하나).

## 퍼즐방
15. 퍼즐은 **손으로 그린 퍼즐 판(puzzles.json)** 을 방 안에 찍어서 만든다. 무작위로 만들지 않는다. 그래서 항상 풀 수 있다.
16. 퍼즐 판의 바깥 한 줄은 걸어 다니는 둘레다(`.`과 레버 `L`만). 판은 방 안쪽에 들어가는 크기여야 하고, 방 가운데에 놓는다. 레버가 방 입구 칸이나 그 상하좌우에 오면 판을 좌우·상하로 뒤집어 다시 맞춰 보고, 그래도 안 되면 다른 판을 고른다. 판 고르기에는 `objects` 난수 흐름을 쓴다. 맞는 판이 없으면 그 방은 퍼즐방이 되지 않는다.
17. 퍼즐방에는 **잠긴 상자**(`chest`, `state.locked: true`)가 판 안에 있다. 잠긴 상자를 열려고 하면 "잠겨 있다."만 남고 턴은 쓰지 않는다.
18. 퍼즐을 풀면 상자가 열린다: "철컥, 상자의 잠금이 풀렸다." 그 뒤 상자를 열면 F005 규칙 12의 퍼즐방 규칙(셋 중 하나).
19. **되돌림 레버:** 판 둘레에 레버(`lever`) 1개가 있다. 레버 쪽으로 방향 입력을 하면(`interact`, 한 턴) 판이 처음 상태로 돌아간다. "덜컥, 퍼즐이 처음으로 돌아갔다." 퍼즐을 푼 뒤에는 레버가 아무것도 하지 않는다.
20. **실패 벌칙은 없다.** 되돌리는 데 쓰는 턴이 곧 비용이다.
21. 몬스터는 퍼즐 판의 칸(발판, 돌, 스위치, 구멍)에 들어가지 않고, 길 찾기에서도 막힌 칸으로 본다.

### 퍼즐 1: 무너지는 발판 (`crumble`)
22. 판 위의 금 간 발판(`plate`)을 **모두 한 번씩** 밟으면 풀린다.
23. 밟은 발판에서 나오면 그 발판은 무너져 구멍이 된다(`state.broken: true`, 지나갈 수 없음, 시야는 막지 않음).
24. 플레이어가 발판 위에 있는데 상하좌우로 갈 수 있는 칸이 하나도 없으면, 그 턴 마무리에 퍼즐이 자동으로 처음으로 돌아가고 플레이어는 판 둘레의 가장 가까운 칸으로 옮겨진다. 메시지 "발밑이 흔들리더니 발판이 다시 솟아올랐다."
25. 풀리면 구멍이 모두 원래 바닥으로 돌아온다.

### 퍼즐 2: 돌 밀기 (`boulder`)
26. 판 위의 모든 스위치(`switch`) 위에 돌(`boulder`)이 올라가면 풀린다.
27. 돌 쪽으로 방향 입력을 하면(`interact`) 돌이 같은 방향으로 한 칸 밀리고 플레이어도 한 칸 따라간다(한 턴). 돌 너머 칸이 바닥이고, 개체·다른 돌·스위치가 아닌 물체가 없을 때만 밀린다. 밀 수 없으면 무효 행동(턴 안 씀).
28. 돌은 지나갈 수 없고 시야를 막지 않는다. 밀쳐내기나 몬스터로는 움직이지 않는다.
29. 스위치는 지나갈 수 있는 바닥 물체다. 돌이 올라가면 눌린다. 돌이 내려가면 다시 떨어진다.

### puzzles.json (신규)
```json
{
  "_note": "퍼즐 판(F009). 문자: . 바닥  # 벽  o 금 간 발판  B 돌  S 스위치  C 잠긴 상자  L 되돌림 레버(판 둘레 쪽 가장자리에)",
  "puzzles": [
    { "id": "crumble_3x3", "type": "crumble", "map": [
      "L....",
      ".ooo.",
      ".oCo.",
      ".ooo.",
      "....."
    ] },
    { "id": "boulder_basic", "type": "boulder", "map": [
      "L.....",
      ".B..S.",
      "......",
      ".#..C.",
      "......"
    ] }
  ]
}
```
- 위 두 개는 형식 예시다. 실제 판은 크기별로 2~3개씩 만들어 넣는다(최소 6종). 판을 추가할 때는 손으로 풀어 보고 넣는다.
- 판의 바깥 한 줄은 둘레 통로로 쓰이므로 `.`과 `L`만 둔다. 판을 뒤집어도 풀 수 있어야 한다(대칭 이동은 풀이를 바꾸지 않는다).
- `crumble` 판에서 잠긴 상자(`C`)는 발판으로 둘러싸여 있어도 된다. 풀리면 구멍이 사라져 갈 수 있다.
- 데이터 검사: 문자 종류, 줄 길이가 같은지, 레버·상자가 정확히 1개, `boulder` 판의 돌 수 ≥ 스위치 수, `crumble` 판의 발판 ≥ 3.
- 개발 테스트: 모든 판에 대해 "풀 수 있음"을 자동으로 확인하는 테스트를 둔다(작은 판이므로 너비 우선 탐색으로 충분하다).

## 샘방
30. 방 가운데에 가장 가까운 빈 칸에 회복의 샘(`spring`) 1개. 지나갈 수 없다.
31. 샘 쪽으로 방향 입력을 하면(`interact`, 한 턴) 최대 HP의 `springHealRatio`(loot.json, 0.5)만큼 회복하고 샘이 마른다(`state.used: true`, 마른 샘 그림). "샘물을 마셨다. (HP +{회복량})"
32. HP가 최대일 때는 마시지 않는다: "지금은 목이 마르지 않다." 턴을 쓰지 않는다.
33. 마른 샘에 다시 가면 "샘이 말라 있다." 턴을 쓰지 않는다.
34. 몬스터는 샘을 쓰지 않는다.

## 이번 버전에서 하지 않는 것
- 미믹(상자로 위장한 몬스터) — 숨은 위험이라 P4와 맞지 않는다
- 상점방 — 화폐가 없다
- 몬스터가 몰려 있는 방(몬스터방)
- 퍼즐 실패 벌칙

## 완료 기준
- [ ] 모든 층에 `start` 1개, 1~9층에 `stairs` 1개, 10층에 `boss` 1개.
- [ ] 시드 1000개로 1~9층을 생성했을 때 보물상자방은 1~2개, 비밀방·퍼즐방·샘방은 0~1개다. 10층에는 이 넷이 없다.
- [ ] 시드 1000개로 생성했을 때 방 종류 비율이 테마 가중치와 ±5%p 안에서 맞는다(최소 개수 보정 제외).
- [ ] 비밀방이 있는 층에서 막다른 통로는 그 입구 하나뿐이고, 비밀방이 없는 층에는 막다른 통로가 없다.
- [ ] 비밀방 바닥은 숨은 벽을 찾기 전에는 시작 지점에서 갈 수 없다.
- [ ] 숨은 벽 옆에서 쉬면 그 벽이 통로가 되고 메시지가 남는다. 옆이 아닌 곳에서 쉬면 아무 일도 없다.
- [ ] 퍼즐방의 잠긴 상자는 풀기 전에 열리지 않고 턴도 안 쓴다.
- [ ] 무너지는 발판: 모든 발판을 한 번씩 밟으면 상자가 열리고 구멍이 사라진다.
- [ ] 무너지는 발판: 갇히면 그 턴 끝에 퍼즐이 처음으로 돌아가고 플레이어가 둘레로 옮겨진다.
- [ ] 돌 밀기: 돌을 스위치에 올리면 상자가 열린다. 벽 쪽으로 미는 입력은 턴을 쓰지 않는다.
- [ ] 레버를 당기면 판이 처음 상태로 돌아가고 한 턴이 지난다.
- [ ] puzzles.json의 모든 판이 풀 수 있다는 자동 테스트가 통과한다.
- [ ] 샘을 마시면 HP가 최대의 50% 회복되고 샘이 마른다. HP가 가득일 때는 마시지 않고 턴도 안 쓴다.
- [ ] 몬스터가 퍼즐 판과 숨은 벽(발견 전)을 지나지 않는다.
