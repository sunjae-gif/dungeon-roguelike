# F017 밸런스 시뮬레이터

## 목적
M5의 밸런스 조정을 감이 아니라 숫자로 한다. 자동 플레이 봇이 수백 판을 돌려서 "몇 층에서 많이 죽는지", "한 판이 몇 턴인지", "어떤 아이템을 가진 판이 잘 깨는지"를 보여준다.
플레이어용 기능이 아니다. 개발 도구다(F012처럼 배포 빌드에 들어가지 않는다).

## 실행
1. `npm run sim -- --runs 500 --seed-start 1` 처럼 실행한다. 브라우저 없이 `core/`만 써서 돈다.
2. 결과는 `sim-results/날짜-시각.json`과 사람이 읽는 요약 `sim-results/날짜-시각.md`로 남긴다. `sim-results/`는 .gitignore에 넣는다.
3. 같은 시드 범위로 다시 돌리면 결과가 같다(봇도 결정적이다).

## 봇 규칙 (단순하고 일정하게)
봇은 "잘하는 사람"이 아니라 "조심성 있는 보통 사람" 정도로 둔다. 실제 사람의 결과는 봇보다 좋다고 보고 해석한다.
매 턴 위에서부터 처음 맞는 것 하나만 한다.
1. `itemChoice`면: 희귀를 먼저, 같은 등급이면 후보 순서대로 첫 번째를 고른다.
2. HP가 최대의 40% 이하이고 회복 물약이 있으면 마신다.
3. 상하좌우로 인접한 몬스터가 있으면 공격한다(여럿이면 HP가 가장 낮은 쪽).
4. 보스의 강타 칸 위에 서 있으면 강타 칸이 아닌 옆 칸으로 비킨다.
5. HP가 최대의 60% 이하이고 회복의 샘을 알고 있으면 샘으로 간다.
6. 보이는 몬스터가 있으면 그쪽으로 다가간다.
7. 열지 않은 상자를 알고 있으면 그쪽으로 간다(퍼즐 상자는 건너뛴다).
8. 아직 안 본 칸이 남아 있으면 가장 가까운 미탐색 칸 쪽으로 간다.
9. 계단으로 가서 내려간다. 10층이면 보스방으로 간다.
- 봇은 함정을 피해서 길을 찾고, 비밀방은 찾지 않고, 퍼즐은 풀지 않는다.
- 한 판이 `maxTurnsPerRun`(5000)턴을 넘으면 "시간 초과"로 끝낸다(봇이 막힌 경우를 잡아낸다).

## 보고서 내용
| 항목 | 설명 |
|---|---|
| 클리어율 | 클리어한 판 / 전체 |
| 사망 층 분포 | 층별 사망 수. 어느 층이 갑자기 어려운지 |
| 사망 원인 순위 | `killedBy`별 횟수 (몬스터, 함정, 중독) |
| 한 판 턴 수 | 평균, 중앙값, 상위 10%. 클리어한 판만 따로 |
| 층별 남은 HP | 층에 들어설 때 HP 비율의 평균 |
| 빌드 아이템 | 아이템별 "가진 판의 클리어율"과 "전체 클리어율"의 차이 |
| 보스전 | 보스방에 들어간 판 중 이긴 비율, 보스전 평균 턴 수 |
| 시간 초과 | 판 수와 시드 (버그 확인용) |

## 목표치 (balance-targets.json, 임시)
```json
{
  "_note": "봇 기준 목표치. 사람은 봇보다 잘한다고 보고 정한다. 실제로 몇 판 해 본 뒤 고친다.",
  "botClearRate": [0.10, 0.30],
  "medianTurnsCleared": [600, 1000],
  "maxShareOfDeathsOnOneFloor": 0.25,
  "bossWinRateWhenReached": [0.35, 0.65],
  "itemClearRateGapWarn": 0.15
}
```
- 한 판 15~20분(P1)을 턴당 약 1~1.2초로 보고 턴 수 목표를 600~1000으로 잡았다. 실제로 몇 판 해 보고 초당 턴 수를 재서 고친다.
- 보고서는 목표 범위를 벗어난 항목에 ⚠️를 붙인다.
- 어떤 빌드 아이템을 가진 판의 클리어율이 전체보다 `itemClearRateGapWarn`(15%p) 넘게 높거나 낮으면 ⚠️를 붙인다(너무 세거나 쓸모없는 아이템 후보).
