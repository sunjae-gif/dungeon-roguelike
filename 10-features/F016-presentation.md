# F016 화면 연출과 다듬기

## 목적
F007이 미뤄 둔 것들(창 맞춤 확대, 이동 연출, 스탠딩 일러스트 위치)을 정한다. 연출은 "무슨 일이 일어났는지"를 더 잘 보이게 하는 데만 쓴다(P4). 연출 때문에 입력이 막히거나 한 판이 느려지면 안 된다(P1).

## 원칙
1. **연출은 `render/`에만 있다.** 규칙 코드(`core/`)는 연출을 모른다. 연출을 모두 꺼도 게임 결과는 같다.
2. **연출은 입력을 막지 않는다.** 연출 중에 새 입력이 오면 진행 중인 연출을 즉시 끝 상태로 보내고 새 입력을 처리한다.
3. 모든 연출 시간은 ui.json `anim`에 둔다. 가장 긴 이동 연출도 키 반복 간격(120ms)보다 짧아야 한다.

## 창 맞춤 확대
4. 게임 화면은 지금처럼 1280×720 기준으로 그린다.
5. 브라우저 창에 맞춰 캔버스 전체를 비율을 유지한 채 확대·축소한다. 남는 부분은 검은 여백.
6. 창이 기준 크기의 정수 배(2배, 3배)를 담을 수 있으면 정수 배율을 쓴다. 그렇지 않으면 창에 맞는 비율로 확대한다.
7. 확대할 때 픽셀아트가 흐려지지 않게 한다(CSS `image-rendering: pixelated`). 스탠딩 일러스트는 매끄럽게 확대한다(별도 레이어).

## 움직임 연출
| 연출 | 내용 | 시간 (ui.json `anim`) |
|---|---|---|
| 이동 | 한 칸을 미끄러지듯 이동 | `moveMs` 80 |
| 공격 | 공격자가 대상 쪽으로 반 칸 나갔다 돌아옴 | `attackBumpMs` 100 |
| 피격 | 맞은 개체가 흰색으로 한 번 깜빡임 | `hitFlashMs` 80 |
| 피해 숫자 | 맞은 칸 위로 숫자가 떠올랐다 사라짐. 회복은 초록 | `damageNumberMs` 500 |
| 원거리 공격 | 공격자에서 대상까지 작은 점이 날아감 | `projectileMs` 100 |
| 보스 힘 모으기 | 강타 칸(F008)이 천천히 깜빡임 | `telegraphPulseMs` 600 (반복) |
| 함정 발동 | 함정 칸이 한 번 번쩍임 | `trapFlashMs` 150 |

- 같은 턴에 여러 몬스터가 움직이면 동시에 움직인다(차례대로 기다리지 않는다).
- 피해 숫자는 겹치면 위아래로 조금씩 비켜 그린다.

## 스탠딩 일러스트
일러스트는 아래 네 곳에서만 쓴다. 전투 중 화면은 지도와 정보에 집중한다.

| 화면 | 일러스트 | 위치 |
|---|---|---|
| 타이틀 | 주인공 기본 (`player_portrait`) | 화면 오른쪽, 제목은 왼쪽 |
| 10층 floorIntro | 심연의 왕 (`final_boss_portrait`) | 화면 가운데 뒤쪽, 반투명으로 떠오름 |
| 게임 오버 | 주인공 쓰러짐 (`player_portrait_defeat`) | 결과 정보 왼쪽 |
| 클리어 | 주인공 승리 (`player_portrait_victory`) | 결과 정보 왼쪽 |

필요한 일러스트는 **4장**이다. 없으면 그 자리를 비우고 나머지를 그대로 그린다.

## 타이틀 화면
- 게임 제목(글꼴 크게), 주인공 일러스트, "Enter: 새 게임", 버전 번호.
- 개발자 모드면 시드 입력 칸.
- 배경은 테마 1의 바닥 타일을 어둡게 깐다.

## 상태창 다듬기
- 빌드 아이템 이름 앞에 아이템 아이콘(16px 원본을 1배로)을 붙인다.
- 일시 효과에도 작은 아이콘을 붙인다(`status_weak`, `status_poison`, `status_rage`).

## ui.json에 추가
```json
"anim": { "moveMs": 80, "attackBumpMs": 100, "hitFlashMs": 80, "damageNumberMs": 500,
          "projectileMs": 100, "telegraphPulseMs": 600, "trapFlashMs": 150 },
"scaling": { "preferInteger": true }
```

## 완료 기준
- [ ] 1920×1080 창에서 게임 화면이 비율을 유지한 채 창을 채우고, 픽셀아트 경계가 흐리지 않다.
- [ ] 2560×1440 창에서는 정확히 2배로 그려진다.
- [ ] 키를 누르고 있을 때 이동 속도(120ms에 한 칸)가 연출 때문에 느려지지 않는다.
- [ ] 연출 도중 다른 키를 누르면 바로 반응한다.
- [ ] ui.json에서 모든 연출 시간을 0으로 하면 연출 없이 지금과 똑같이 동작한다.
- [ ] 일러스트 파일이 없어도 네 화면이 깨지지 않는다.
- [ ] `core/`에 연출 관련 코드가 없다.
