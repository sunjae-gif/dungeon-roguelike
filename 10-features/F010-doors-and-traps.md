# F010 문과 함정

## 목적
문은 시야를 끊어 "저 너머에 뭐가 있을까"를 만들고, 함정은 무작정 달리지 않고 살피게 만든다.

## 물체 종류
칸 종류는 `wall`/`floor`로 고정이므로, 문·숨은 벽·함정은 모두 `floor` 칸 위의 물체다(30-systems/game-state.md).

| type | 이름 | state | blocksMove | blocksSight |
|---|---|---|---|---|
| `door` | 문 | `{ open: false }` | 닫혀 있으면 true (부딪히면 열림) | 닫혀 있으면 true |
| `hiddenWall` | 숨은 벽 | `{ discovered: false }` | 발견 전 true | 발견 전 true. 화면에는 벽으로 그림 |
| `trap` | 함정 | `{ revealed: false }` | false (밟으면 발동) | false |

## 문 규칙
1. 문은 방과 통로가 만나는 칸에 생긴다. 생기는 확률은 themes.json `doorChance`.
2. 닫힌 문으로 이동하면 문이 열리고 플레이어는 제자리에 있다. 한 턴을 쓴다.
3. 열린 문은 다시 닫히지 않는다.
4. 몬스터도 문을 연다.

## 함정 규칙
1. 함정은 방과 통로의 바닥 칸에 놓인다. 개수와 종류는 테마 설정(themes.json `trapCount`, `trapTypes`)과 traps.json.
2. 시작방에는 함정을 놓지 않는다.
3. 함정 칸에 들어가면 발동한다. 효과는 traps.json.
4. 함정은 한 번 발동하면 드러나고, 드러난 함정은 지도에 표시된다.

## 예외·엣지 케이스
- 문과 함정이 놓여도 F001의 "모든 바닥 칸에 닿을 수 있음"은 유지되어야 한다. 함정 칸은 지나갈 수 있으므로 길을 막지 않는다.
- 통로 폭이 1칸이라 함정을 피할 길이 없는 경우가 생긴다. 이것을 허용할지는 아래 미결정 사항.

## 완료 기준
- [ ] 닫힌 문 너머 칸은 시야에 들어오지 않는다.
- [ ] 닫힌 문으로 이동하면 문이 열리고, 위치는 그대로, 턴 수가 1 늘어난다.
- [ ] 시작방 안에 함정이 없다.
- [ ] 함정을 밟으면 traps.json의 효과가 적용되고 그 함정이 "드러남" 상태가 된다.

## 미결정 사항
- [ ] **함정은 밟기 전에 보이는가?** P4(위험은 미리 보인다)와 부딪힌다. 선택지: 처음부터 보임 / 인접하면 보임 / 숨어 있지만 바닥에 흔적 / 탐색 아이템이 있어야 보임
- [ ] 드러난 함정을 다시 밟으면 또 발동하는가?
- [ ] 몬스터도 함정을 밟는가? (밟는다면 함정으로 몬스터를 유인하는 플레이가 생긴다)
- [ ] 잠긴 문과 열쇠가 있는가?
- [ ] 함정 종류: 가시(피해) 외에 무엇을 넣을지 (독, 순간이동, 몬스터 소환, 경보)
