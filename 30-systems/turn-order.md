# 턴 순서

`playing` phase에서 한 턴이 처리되는 순서. 모든 기능이 이 순서를 따른다.
이벤트 이름은 effects.md, 화면 전환은 game-flow.md.

## 플레이어 행동 종류
| 행동 | 발생 조건 | 턴을 쓰는가 |
|---|---|---|
| `move` | 지나갈 수 있는 칸으로 방향 입력 | 쓴다 |
| `attack` | 몬스터가 있는 칸으로 방향 입력 | 쓴다 |
| `interact` | 막힌 물체(닫힌 문, 닫힌 상자 등)가 있는 칸으로 방향 입력 | 쓴다 |
| `rest` | Space | 쓴다 |
| `useItem` | 숫자키 | 효과가 있으면 쓴다 |
| `descend` | 계단 위에서 `>` / Enter | 쓴다 (층 이동, F013) |
| 무효 | 벽 방향, 효과 없는 아이템, 계단 아닌 곳에서 `>` | 안 쓴다 |

방향 입력은 대상 칸에 따라 `attack` → `interact` → `move` → 무효 순서로 판정한다.

## 한 턴의 순서
1. **입력 대기.** 입력이 없으면 아무것도 바뀌지 않는다.
2. 입력을 행동으로 바꾼다. 무효 행동이면 아무것도 바뀌지 않고 여기서 끝난다(턴 수 그대로, 메시지 없음).
3. `onTurnStart` 이벤트.
4. **플레이어 행동 처리.**
   - `move`면 이동 후 `onMove`, 그다음 도착한 칸의 처리: 아이템 자동 줍기(`onPickup`) → 함정 발동(`onTrapTriggered`, 피해면 `onDamaged`).
   - `descend`면 새 층을 만들고 `onFloorEnter` 후 phase를 `floorIntro`로 바꾸고 **이 턴을 끝낸다**(5~6 건너뜀, 턴 수는 1 증가).
5. **몬스터 행동.** 살아 있는 몬스터가 `id` 순서대로 한 번씩 행동한다(F004). 몬스터 속도 차이는 없다. 각 몬스터 행동 뒤 플레이어 HP가 0 이하면 남은 몬스터는 행동하지 않는다.
6. **턴 마무리.**
   1. `onTurnEnd` 이벤트, 일시 효과의 `turnsLeft` 1 감소·만료 제거
   2. 시야 다시 계산, 탐색됨 갱신
   3. 게임 오버 판정 → 클리어 판정 (game-flow.md)
   4. 턴 수 1 증가

## 같은 턴에 겹치는 경우
- 플레이어의 공격으로 몬스터가 죽으면, 그 몬스터는 5단계에서 행동하지 않는다.
- 함정으로 플레이어 HP가 0 이하가 되면 5단계를 건너뛰고 6단계로 간다.

## 완료 기준
- [ ] 무효 행동 뒤에는 턴 수와 몬스터 위치가 그대로다.
- [ ] 아이템과 함정이 같은 칸에 있을 수 없으므로(game-state.md) 처리 순서 충돌이 없다.
- [ ] 플레이어가 먼저 쓰러뜨린 몬스터는 같은 턴에 공격하지 않는다.
- [ ] 계단을 내려간 턴에는 이전 층 몬스터가 행동하지 않는다.

## 미결정 사항
- [ ] 몬스터도 함정을 밟는가? (F010과 같은 질문)
