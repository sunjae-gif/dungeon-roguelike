# 난수 규칙

## 목적
- 같은 시드면 같은 판이 나와야 한다. 버그 재현과 테스트에 필요하다.
- 기능 하나를 추가해 난수 호출이 늘어나도, **관계없는 부분의 결과는 바뀌지 않아야 한다.** 그래야 함정을 추가했다고 몬스터 배치 테스트가 깨지지 않는다.

## 규칙
1. 난수는 `core/rng.ts`로만 만든다. `Math.random()`, `Date.now()`, `crypto`를 규칙 코드에서 쓰지 않는다.
2. 생성기는 32비트 정수 상태를 쓰는 작고 결정적인 알고리즘(예: mulberry32)을 쓴다. 상태가 숫자 하나라서 `RunState.rng`에 그대로 저장된다.
3. 판 시드(`runSeed`)는 0 이상 2³²−1 이하의 정수다. 판 시드를 새로 뽑는 곳은 타이틀 화면에서 "새 게임"을 누를 때 한 곳뿐이다. 여기서만 `Date.now()`를 쓸 수 있다.
4. 시드는 화면에 8자리 16진수로 보여준다(예: `3FA2C910`).

## 난수 흐름 (stream)
쓰임새마다 따로 된 난수 흐름을 쓴다. 각 흐름의 시작값은 `hash(runSeed, 층 번호, 흐름 이름)`으로 만든다.

| 흐름 이름 | 쓰는 곳 | 범위 |
|---|---|---|
| `map` | 방 배치, 통로, 비밀방 입구의 막다른 통로 (F001, F009) | 층마다 새로 |
| `rooms` | 방 종류 배정 (F009) | 층마다 새로 |
| `objects` | 문, 함정, 상자, 퍼즐 판 고르기, 샘 배치 (F009, F010) | 층마다 새로 |
| `spawn` | 몬스터 배치 (F004) | 층마다 새로 |
| `loot` | 바닥 아이템, 상자 내용물(빌드 아이템 후보), 몬스터 드롭 (F005) | 층마다 새로 (층 안에서는 이어 씀, 아래) |
| `combat` | 전투 중 무작위 요소 (있다면) | 판 전체 |
| `ai` | 몬스터 행동 중 무작위 선택 | 판 전체 |

- "층마다 새로" 흐름은 층을 만들 때 시작값에서 다시 출발한다. 같은 판 시드라면 그 층의 생성 결과는 플레이어가 그 전에 무엇을 했든 같다.
- "판 전체" 흐름은 층 번호 자리에 0을 넣어 시작하고, 현재 상태를 `RunState.rng`에 저장해 이어 쓴다.
- `loot`는 층을 만들 때 시작값에서 출발해 바닥 아이템을 놓고, **그 뒤 그 층에 있는 동안**(상자 열기, 몬스터 드롭) 현재 상태를 `RunState.rng.loot`에 저장해 이어 쓴다. 다음 층을 만들면 다시 시작값에서 출발한다. 그래서 층 생성 결과는 플레이와 상관없이 같고, 층 안의 상자·드롭 결과는 그 층에서 한 행동에 따라 달라진다.
- 새 쓰임새가 생기면 기존 흐름에 끼워 넣지 말고 이 표에 새 흐름을 추가한다.
- `hash`는 문자열과 숫자를 섞어 32비트 정수를 만드는 결정적 함수(예: FNV-1a)다.

## 완료 기준
- [ ] 같은 runSeed로 만든 1~10층이 모두 칸·물체·몬스터 단위로 같다.
- [ ] `objects` 흐름의 호출 횟수를 바꿔도 `map`, `spawn` 흐름의 결과는 같다.
- [ ] RunState를 JSON으로 저장했다 복원한 뒤 진행한 결과가, 저장하지 않고 진행한 결과와 같다.
- [ ] 규칙 코드(`src/core/`)에 `Math.random`이 없다. (테스트로 소스 검사)
